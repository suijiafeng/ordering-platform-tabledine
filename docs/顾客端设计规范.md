# 顾客端设计规范

顾客端 H5（`customer-web/`）的视觉基线来自 Figma「手机扫码点餐」，令牌值由设计源文件实测得出，
不是目测近似值。新增页面一律沿用本文的令牌与基元，不要新造色值、字号和圆角。

## 一条原则

**页面用 `components/ui.tsx` 的基元搭建，样式写在 `app/globals.css`。**
antd-mobile 只用于行为类组件（`Popup`、`Dialog`、`PullToRefresh`、`InfiniteScroll`），
不用它的 `Button`、`Stepper`、`NavBar`、`SearchBar`、`Tag`、`Form`、`Steps` 等外观类组件，
也不要再写 CSS 去覆盖它们——过去那样做的结果是处处差一点。

## 色板

| 用途 | 令牌 | 值 |
| --- | --- | --- |
| 品牌主色（按钮、价格、强调） | `--brand` | `#F5562B` |
| 首字方块底 / 选中项底 | `--brand-wash` `--brand-wash-2` | `#FFF3EA` `#FFF1E8` |
| 桌号条 | `--brand-strip` / `--brand-strip-ink` | `#FFF7F0` / `#B25A1B` |
| 首字方块的字 | `--tile-ink` | `#D97B3F` |
| 主文字 / 正文 / 标签 / 说明 / 占位 | `--ink` … `--ink-5` | `#1A1A1A` `#333` `#666` `#999` `#BDBDBD` |
| 分区线 / 卡内线 / 更弱 / 控件描边 | `--line` `--line-2` `--line-3` `--border` | `#EEE` `#F0F0F0` `#F5F5F5` `#D9D9D9` |

已完成 `#E9F7EE`/`#2BA94F`，失败 `#FDECEA`/`#F5222D`，已关闭用 `--line-2`/`--ink-4`。

## 字阶

22px Bold 页面主标题（店名、订单状态、支付成功）；18px Medium 顶栏标题与桌号；
36px Bold 收银台金额；15px Medium 菜品名与小节标题；14px 正文与键值行；
13px 次要说明；12px 注释；11px 菜品简介等最小字号。只用 Regular(400)、Medium(500)、Bold(700)。

## 尺寸

卡片圆角 14px，页面左右留白 12px，卡片内留白 16px。
按钮一律胶囊形：大 54px 高 / 17px 字，中 52px / 16px，小 34px / 14px。
输入框与选项 chip 高 36~54px，chip 圆角 18px。顶栏 56px，底部固定条 87px（两行时 118px）。
步进器：减号 26px 描边圆（2px `--border`），加号 26px 实心品牌色圆，中间数字 32px 宽无底色。

## 基元

`AppBar` `PillButton` `Stepper` `Tag` `Chip` `Card` `Tile` `Price` `BottomBar` `CenterState` `Spinner`，
以及 `SearchIcon` / `CartIcon` / `CheckIcon`（内联 SVG，不用 emoji，跨平台渲染不一致）。

常用组合类：`.kv` 键值行（灰标签 + 深色值，`.strong` 为合计行），`.li` 明细行（名称 / ×N / 金额），
`.card-title` 小节标题，`.body-pad` 页面内容区留白。

## 反馈与状态

设计稿第 11、12 屏定义了全套反馈模式，都已做成基元，新页面直接复用：

| 场景 | 用法 | 外观 |
| --- | --- | --- |
| 操作成功的轻提示 | `notify('已加入购物车')` | 屏幕居中黑色胶囊，48px 高，圆角 24，14px 白字，2.2 秒自动消失。只有一种样式，不分成功 / 普通 |
| 需要确认的操作 | `await confirmDialog('确定取消订单吗？', '取消后需重新下单', '确定取消')` | 居中白卡，17px 加粗问句标题 + 13px 灰色后果说明，底部左描边右主色两颗 48px 胶囊按钮 |
| 只需告知结果 | `await alertDialog('退款申请已提交', '商家审核后将原路退回余额')` | 同上，底部单颗整宽主色按钮「知道了」 |
| 列表 / 页面没有内容 | `<EmptyState title="还没有订单" desc="下单后可在这里查看进度" action={…} />` | 80px 浅灰圆 + 一个字，16px 标题，13px 说明，160×48 主色按钮；卡片内用 `inset` 收窄留白 |
| 加载中 | `<Skeleton rows={4} label="订单加载中…" />` | 灰条占位，不用转圈，避免白屏闪烁 |
| 断网 | 全局 `<OfflineBanner />`（已挂在 layout） | 顶部吸附浅橙条 + 圆形「!」，`navigator.onLine` 驱动 |
| 表单校验失败 | `.field.invalid` + `<FieldError>` | 输入框 2px 红边 + 浅橙底，下方 12px 红色说明；提交按钮未填完时用禁用灰 |

弹窗文案统一「问句标题 + 后果说明」：标题问「确定…吗？」，说明写清后果，主按钮用动词（确定取消 / 重新支付 / 提交退款），
次按钮用「再想想 / 稍后再说」，不要用含糊的「确定 / 取消」。

## 宽度自适应

**外部容器不设固定宽度，内部跟随容器自适应。** `.app-shell` 是 `width: 100%`，
固定条用 `left: 0; right: 0`，弹层跟随视口满宽，内容区只给内边距、不给 `max-width`。

不要为了「大屏好看」给内容加收口居中或断点分栏——那等于又把宽度写死了。
内容自然填满可用宽度即可。

例外（都不是布局容器，而是组件自身的尺寸）：
- `.dialog` 居中浮层，用设计稿的卡片宽度 `min(100% - 48px, 291px)`
- `.toast` `max-width: 84vw`、`.appbar-title` `max-width: calc(100% - 120px)`，都是相对值，防止贴边

## 吸顶（appbar / 筛选条）

顶栏 `.appbar` 和订单筛选条 `.order-filter` 都是 `position: sticky`，基准是视口。
**外层容器一旦成为滚动容器，里面的 sticky 全部失效**（它以容器为基准，而容器自己不滚动）。
最容易踩的一条：`overflow-x: hidden` 会让浏览器把 `overflow-y` 算成 `auto`，容器就成了滚动容器。
横向裁切一律用 `overflow-x: clip`——同样裁掉横向溢出，但不创建滚动容器。
`.app-shell` 就是这么从坏掉修回来的。

同理不要给页面容器加 `height: 100vh` + `overflow: auto`（让 body 滚）；
多层吸顶时下一层的 `top` 要算上上一层的高度，例如筛选条 `top: calc(56px + var(--safe-top))`。

## 安全区（刘海屏 / Home 指示条）

`viewport` 设了 `viewportFit=cover`，页面会铺到状态栏和 Home 指示条下面，**吸顶 / 吸底的元素必须自己让出安全区**。
`.app-shell` 上定义了三个变量，所有地方统一用它们，不要再直接写 `env()`：

```css
--safe-top     /* 状态栏 / 刘海 */
--safe-bottom  /* Home 指示条 */
--safe-x       /* 横向（横屏、曲面屏） */
```

已处理：顶栏 `.appbar`（高度 `56px + --safe-top`，品牌色/白色会填满刘海区而不是留白）、菜单橙色头、
断网横幅、底部固定条 `.bottom-bar` / `.cart-bar`（高度 `87px + --safe-bottom`，左右用 `max(16px, --safe-x)`）、
底部弹层 `.sheet-pad`、登录页与支付成功页。订单筛选条的吸顶位置也跟着顶栏下移。

联调验证：在控制台给 `.app-shell` 设 `--safe-top: 47px; --safe-bottom: 34px`（iPhone 14 Pro 的值）即可看出效果。

## 加载态

**只在首屏加载用骨架屏，下拉刷新和轮询不要用**（已有内容时闪一下骨架比不闪更糟）。
骨架的版式必须和真实内容对得上，对不上就不如直接转圈：

- `<Skeleton variant="media" />`：左图右文的列表 → 菜单菜品行
- `<Skeleton variant="card" />`：一张张卡片 → 订单列表、订单详情、我的、余额明细
- 提交类操作（支付中）用按钮自身的 loading 态或整页文案，不要用骨架屏

## 文字与容器溢出

移动端一行放不下的内容很多，新增布局时按这几条处理，并在 375px 宽下用超长文案自测：

- 标题类（店名、菜品名、订单菜品串、购物车行名）用 `-webkit-line-clamp` 限制 1~2 行
- 单行信息（桌号、顶栏标题、金额、明细摘要）用 `text-overflow: ellipsis` + `white-space: nowrap`
- flex 布局里，会被挤压的一侧加 `min-width: 0`，不该被挤压的一侧（按钮、金额）加 `flex: none`
- 用户输入（备注、退款原因）和订单号加 `word-break: break-word`
- 按钮文案可能变长的地方（弹窗、空状态）允许折行：`white-space: normal` + `min-height` 代替固定 `height`

## 文案

这是点餐场景，不是银行或后台系统。写文案时：

- **不用金融 / 财会词**：流水、账户余额、款项、原路退回、扣款、入账 →
  明细、余额、金额、退回到余额、抵扣。页面叫「余额明细」而不是「余额流水」。
- **不用技术词**：服务端、接口、token、幂等、状态码不出现在任何顾客可见的文案里。
- 用顾客的说法：菜品而不是商品，点餐而不是下单消费，还没选菜而不是未选购商品。
- 提示要给出下一步：「余额不足，请联系店员充值」好过「余额不足」。
- 入口名称跟页面标题保持一致（「我的」「我的订单」「余额明细」）。

## 约定

- 菜品无图时用 `Tile` 显示名称首字，不要放灰色占位图。
- 金额一律 `¥` 比数字小一号（用 `Price`），带「起」等后缀时后缀为灰色小字。
- 页面底部有固定条时，容器加 `.screen.has-bar`（两行条用 `.has-bar-tall`），否则内容会被遮住。
- 所有 `dvh` 前先写一条 `vh` 作回退，旧内核不支持 `dvh`。
- 设计稿里的餐位费、优惠券、月售、评价、催一下、微信 / 支付宝支付在当前后端没有对应能力，
  暂未实现；若后续补上，沿用上面的令牌即可。
- 新增 CSS 类名不要用 `.empty`、`.active` 这类过于通用的词做根类，容易误中别处的修饰类
  （`.empty` 就曾把购物车空车标记 `.cart-ball.empty` 一起命中，把圆标撑变形）。
