# 上线清单（MVP）

> 按顺序勾选。前 3 节是外部前置条件，没有它们无法做真实支付联调；第 4 节起是工程动作。

## 1. 主体资质（需求 §2，周期最长，最先启动）

> 会员余额模式下，微信支付商户号、支付宝签约与证书配置都**不是必需**的；小程序注册、备案、域名仍然需要。

- [ ] 营业执照 + 对公账户 / 法人账户
- [ ] 微信小程序注册（企业主体）并认证；记录 `AppID` / `AppSecret`
- [ ] 微信支付商户号开通，关联小程序 AppID，申请 JSAPI 支付权限
- [ ] 微信支付 APIv3：下载商户 API 证书（`apiclient_key.pem`、证书序列号），设置 APIv3 密钥，获取微信支付公钥及公钥 ID
- [ ] 支付宝小程序创建并上线前准备；记录 `AppID`
- [ ] 支付宝：生成应用密钥（RSA2），配置应用公钥，记录支付宝公钥；签约「小程序支付」
- [ ] 域名已备案（ICP），解析到服务器

## 2. 小程序平台配置

**微信公众平台 → 开发 → 开发管理**
- [ ] 服务器域名：`request` 合法域名加 `https://<域名>`；`uploadFile` / `downloadFile` 同上（图片）
- [ ] 业务域名（如需 webview）：不需要
- [ ] 「扫普通链接二维码打开小程序」：规则 `https://<域名>/q/`，前缀占用；下载校验文件放到 `deploy/nginx/html/` 根目录；测试链接先用开发版验证，**发布后全量生效**
- [ ] 支付：微信支付商户平台 → 产品中心 → 开发配置，确认 JSAPI 支付授权目录（小程序无需目录）
- [ ] 支付回调地址在后端配置 `PAY_NOTIFY_BASE_URL=https://<域名>`，实际回调 `https://<域名>/api/v1/pay/notify/wechat` 与 `/wechat-refund`

**支付宝开放平台 → 小程序 → 设置**
- [ ] 开发设置 → 服务器域名白名单：`https://<域名>`
- [ ] 「扫普通二维码打开小程序」：规则 `https://<域名>/q/`，同样需要校验文件
- [ ] 支付异步通知地址 `https://<域名>/api/v1/pay/notify/alipay`（后端在下单时传入，无需平台配置，但域名需在白名单）

## 3. 服务器与部署

- [ ] 服务器安装 Docker + Docker Compose v2
- [ ] 后端镜像默认 `SPRING_PROFILES_ACTIVE=prod`；非 dev/test 环境下若模拟登录 / 模拟支付开启或使用开发密钥会**拒绝启动**（看 `docker compose logs backend`）
- [ ] `cp deploy/.env.example deploy/.env`，逐项填写：
  - `DB_PASSWORD`、`JWT_SECRET`（`openssl rand -base64 48`）
  - `QR_BASE_URL=https://<域名>/q/`、`PAY_NOTIFY_BASE_URL=https://<域名>`
  - `WECHAT_APP_ID` / `WECHAT_APP_SECRET`
  - `WECHAT_PAY_MCH_ID` / `WECHAT_PAY_SERIAL_NO` / `WECHAT_PAY_PRIVATE_KEY` / `WECHAT_PAY_API_V3_KEY` / `WECHAT_PAY_PLATFORM_PUBLIC_KEY_ID` / `WECHAT_PAY_PLATFORM_PUBLIC_KEY`
  - `ALIPAY_APP_ID` / `ALIPAY_PRIVATE_KEY` / `ALIPAY_PUBLIC_KEY`（三者都必填，缺公钥无法验签，视为未配置）
  - 微信 `WECHAT_PAY_PLATFORM_PUBLIC_KEY` 同样必填（回调与应答验签）
  - `BOOTSTRAP_*`：首次启动创建门店与店主，成功后改回 `BOOTSTRAP_ENABLED=false`
- [ ] 替换 `deploy/nginx/conf.d/ordering.conf` 中的 `ordering.example.com`
- [ ] 首次签发 Let's Encrypt 证书（见 README「生产部署」第 4 步）
- [ ] `cd merchant-web && npm ci && npm run build`；`cd deploy && docker compose up -d --build`
- [ ] `docker compose ps` 全部 healthy；`curl https://<域名>/api/v1/c/stores/1` 返回店铺
- [ ] 用店主账号登录商家端，立刻修改初始密码（顶栏「修改密码」）
- [ ] 店铺设置：名称、营业时间、接单模式、三个超时参数
- [ ] 菜品、桌台录入；下载并张贴桌码

## 4. 小程序构建与配置

- [ ] `miniapp/.env.production`：`TARO_APP_API_BASE=https://<域名>`
- [ ] `project.config.json` / `mini.project.json` 填入正式 AppID
- [ ] `npm run build:weapp` → 微信开发者工具导入 `dist/weapp`，上传为体验版
- [ ] `npm run build:alipay` → 支付宝开发者工具导入 `dist/alipay`，上传为体验版
- [ ] 体验版打开「不校验合法域名」关闭，确认真实域名可访问
- [ ] H5：`npm run build:h5` → `dist/h5`（docker-compose 已挂载到 Nginx `/h5/`）；用手机浏览器打开 `https://<域名>/q/<桌码token>` 能进入点餐页

## 4a. 会员余额模式（三端主流程，不接微信 / 支付宝支付）

- [ ] 商家端「会员充值」开户一个测试会员，充值 0.10 元
- [ ] 手机浏览器扫桌码（H5）、微信扫码（微信小程序）、支付宝扫码（支付宝小程序）各走一遍：浏览菜单 → 加购 → 提交订单时跳转登录 → 登录后回到确认订单页 → 「余额支付」→ 订单变为待接单，余额减少
- [ ] 余额不足时提交：提示「账户余额不足」，订单停留在待支付，余额不变
- [ ] 顾客取消待接单订单 / 商家拒单 / 店主退款：余额立即返还，会员页流水出现「退款返还」
- [ ] 店主重置会员密码 / 停用会员：该会员需重新登录 / 不能登录
- [ ] 看板「今日会员充值」与导出 CSV 中渠道显示「余额」

## 5. 真机联调（仅当日后重新启用微信 / 支付宝支付时需要；会员余额模式见 4a）

> 先在商家端把一道菜改成 0.01 元专用于测试；跑完后下架。微信、支付宝各跑一遍。

| # | 用例 | 预期 |
|---|---|---|
| 1 | 用微信扫桌码 | 打开微信小程序，显示正确店铺与桌号 |
| 2 | 用支付宝扫同一个码 | 打开支付宝小程序，店铺桌号一致 |
| 3 | 用相机 / 其他 App 扫码 | 打开 `/q/{qrToken}` 匿名菜单，显示正确店铺与桌号，可分类浏览 / 搜索 / 查看规格，下单引导使用微信或支付宝小程序 |
| 4 | 商家端重置该桌码后再扫旧码 | 提示「桌码已失效」 |
| 5 | 商家端打烊后下单 | 可浏览菜单，提交订单被拒 |
| 6 | 下单 0.01 元并支付 | 拉起收银台 → 支付成功 → 订单详情显示「待商家接单」；商家端 5 秒内出现并有提示音 |
| 7 | 下单后取消支付 | 订单待支付，可在订单详情「继续支付」 |
| 8 | 待支付不付款等 15 分钟 | 自动关闭 |
| 9 | 待接单时顾客取消 | 自动退款，订单已取消，1 分钟内收到退款到账通知 |
| 10 | 商家接单 → 出餐 → 送达 | 顾客端状态同步（≤5 秒） |
| 11 | 制作中顾客申请退一道菜（0.01） | 商家端退款待审核 → 同意 → 退款成功，订单部分退款 |
| 12 | 商家拒单 | 自动全额退款 |
| 13 | 商家主动自定义金额退款（店主） | 成功；店员账号操作返回无权限 |
| 14 | 手动接单 10 分钟不接 | 自动取消并退款 |
| 15 | 流水导出当天 CSV | 订单与退款行金额与渠道对账单一致 |

- [ ] 核对微信支付商户平台 / 支付宝商家中心的交易与退款记录，与后端 `payment` / `refund` 表一致
- [ ] 查看后端日志无 `ERROR`（`docker compose logs backend | grep ERROR`）

## 6. 提审与发布

- [ ] 浏览器菜单：手机 Safari / Chrome 验证有效桌码、失效桌码、打烊、售罄、空菜单、断网与重试；不登录即可浏览，不出现下单支付接口请求
- [ ] `/q/assets/menu.js`、`/q/assets/menu.css` 返回正确内容类型；缺失资源返回 404；现有微信 / 支付宝扫码进小程序规则保持正常

- [ ] 微信：小程序后台填写类目（餐饮 → 点餐）、隐私协议、用户隐私保护指引（收集：微信昵称头像可不收集；本项目仅用 openid）
- [ ] 支付宝：类目、服务协议
- [ ] 提交审核时附测试桌码截图和说明：审核人员扫码即可体验，无需账号
- [ ] 审核通过后发布正式版；**发布后立即重扫桌码验证普通二维码规则已全量生效**
- [ ] 把测试菜品下架、删除测试订单（或保留并在导出时按日期排除）

## 7. 运维基线（上线当天完成）

- [ ] 数据库备份 cron：`docker compose exec -T postgres pg_dump -U $DB_USERNAME ordering | gzip > /backup/ordering-$(date +%F).sql.gz`，保留 7 天以上
- [ ] 探活：Uptime Kuma 或任意探活服务监控 `https://<域名>/api/v1/c/stores/1`
- [ ] 日志：`docker compose logs -f backend` 可查；退款失败、定时任务异常都以 `ERROR` / `WARN` 记录
- [ ] 商家端「退款管理 → 失败」每天看一次（退款失败需人工重试或线下退款）
- [ ] 支付证书到期提醒（微信商户 API 证书 5 年；Let's Encrypt 自动续期，检查 certbot 容器在跑）
